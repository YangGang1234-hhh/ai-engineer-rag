# AI-Engineer-RAG 产品需求文档（MVP v0.1）

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 项目名称 | AI-Engineer-RAG |
| 项目定位 | 面向 AI 应用开发学习者的、可追溯且可评估的技术知识库问答系统 |
| 当前版本 | MVP v0.1 |
| 文档状态 | 待评审，可修改 |
| 目标 | 做出一个能展示完整 RAG 工程闭环的开源作品，而非通用的“上传文件聊天”工具 |

## 2. 背景与问题

学习 RAG、Agent、LLMOps 等 AI 工程主题时，资料分散在官方文档、技术文章、论文笔记、GitHub README 和个人笔记中。搜索结果常常缺少上下文，直接问大模型又容易得到没有出处或不够可靠的回答。

本项目要解决的问题是：让学习者能将可信技术资料沉淀为一个知识库，并针对问题获得**有明确引用来源、可回到原文核验、可量化评估质量**的回答。

## 3. 目标用户

### 核心用户

- 正在学习或转行 AI 应用开发的开发者。
- 需要系统复习 RAG、Agent、LLMOps 的求职者。
- 希望沉淀个人技术知识库的工程师。

### 用户特征

- 会阅读中英文技术文档。
- 能接受 Markdown、URL 等资料导入方式。
- 关心答案是否可靠，以及为什么系统找到了这些资料。

## 4. 用户场景

### 场景 A：带依据的技术问答

用户问：“RAG 里什么时候有必要使用 rerank？”

系统从知识库召回相关材料，生成简洁回答，并显示每个关键结论所依据的文档标题、片段和原始链接。用户可以打开来源核验。

### 场景 B：资料检索与筛选

用户需要查找“官方文档中关于 LangGraph memory 的说明”，并筛选来源类型为“官方文档”。

系统返回按相关度排序的知识片段，展示标题层级、来源、更新时间和得分。

### 场景 C：RAG 策略实验

开发者希望比较“向量检索”和“混合检索 + rerank”在一组问题上的效果。

系统运行评测集，输出 Hit Rate、MRR、延迟等指标，并保留每个问题的召回结果，便于分析问题。

## 5. 产品目标与成功标准

### 5.1 MVP 目标

1. 完成从资料导入到带引用问答的最小闭环。
2. 支持向量检索、关键词检索和混合检索的对比。
3. 内置可复现的评测数据集与评测脚本。
4. 使用 Docker Compose 让他人可以在本地启动体验。

### 5.2 MVP 验收标准

| 维度 | 验收条件 |
| --- | --- |
| 资料导入 | 可导入 Markdown 和 URL；保存原始来源、标题、时间和标签等元数据 |
| 索引 | 文档被切分为可追踪 chunk，并可重新构建索引 |
| 检索 | 支持向量、BM25/全文和混合检索；结果显示来源与得分 |
| 问答 | 回答包含引用；无足够证据时明确说明无法依据知识库回答 |
| 评测 | 至少 30 道覆盖 RAG、Agent、LLMOps 的评测问题；可输出检索指标 |
| 可复现 | README 给出启动步骤，Docker Compose 可启动所需服务 |

### 5.3 质量目标（首版基线）

- 评测集 Recall@5 不低于 0.70。
- 每个正常回答至少包含 1 条可访问的来源引用。
- 基准数据集上单次检索 P95 延迟目标小于 2 秒（不含大模型生成）。
- 对于知识库没有依据的问题，回答应拒绝编造，并返回“未检索到足够证据”。

这些是初始目标。完成第一批真实数据和评测集后，再根据基线结果调整。

## 6. 功能范围

### 6.1 MVP 必做

#### 资料管理

- 导入本地 Markdown 文件。
- 导入单个公开 URL，并提取正文。
- 为资料保存：标题、来源 URL、来源类型、导入时间、标签、内容哈希。
- 支持查看导入状态与失败原因。

#### 文档处理与索引

- 清洗正文，保留 Markdown 标题层级、代码块和链接。
- 使用“按标题优先 + 长度兜底”的 chunk 策略。
- 每个 chunk 保存所属文档、章节路径、位置、内容和元数据。
- 生成 embedding 并写入向量索引；同时建立关键词/BM25 索引。
- 支持对集合执行重新索引。

#### 检索与问答

- 支持三种模式：向量检索、关键词检索、混合检索。
- 支持按来源类型、主题标签过滤。
- 返回候选 chunk 的得分、标题和来源。
- 基于召回内容生成回答。
- 回答按“结论 / 说明 / 证据来源 / 延伸阅读”组织。
- 引用必须指向具体文档和 chunk；证据不足时拒答。

#### 评测与观测

- 提供 JSONL 格式评测集与运行命令。
- 至少计算 Hit Rate@k、Recall@k、MRR、检索延迟。
- 保存每次评测使用的策略和结果，支持策略间对比。
- 记录一次问答的 query、召回 chunk、最终引用和耗时，便于排查。

#### 交互与交付

- 提供 REST API 和一个轻量 Web 页面或 API 调试页。
- 页面可输入问题、选择检索模式、查看答案及引用。
- 提供 `docker-compose.yml`、`.env.example`、示例数据和 README。

### 6.2 MVP 暂不做

- 多用户注册、权限体系和团队协作。
- 大规模爬虫、自动全站抓取或复杂反爬处理。
- PDF、图片 OCR、音视频转录等多模态解析。
- 在线编辑知识图谱。
- 自动生成完整学习路径、题库和错题系统。
- 云端生产部署、计费与配额。

这些功能可以作为后续迭代项，避免第一版范围失控。

## 7. 核心用户流程

```text
准备资料
  -> 导入 Markdown / URL
  -> 解析、切分、建立索引
  -> 用户提出问题并选择检索模式
  -> 召回、融合排序（可选 rerank）
  -> 基于证据生成回答
  -> 展示引用，用户打开原文核验
  -> 使用评测集比较不同策略
```

## 8. 关键业务规则

1. 每条 chunk 必须能追溯到原始文档和章节位置。
2. 生成回答只能依据本次传入的大模型上下文；不得把模型常识伪装成知识库结论。
3. 关键事实性结论必须有引用，引用必须来自本次检索结果。
4. 检索分数低于阈值或证据不足时，系统应说明限制，而不是强行作答。
5. 相同内容重复导入时，系统应根据内容哈希提示重复或跳过。
6. 评测运行必须记录模型、embedding、chunk 策略、检索策略、top-k 和时间，保证结果可复现。

## 9. 主要数据对象

| 对象 | 关键字段 | 用途 |
| --- | --- | --- |
| Document | id、title、source_url、source_type、tags、content_hash | 原始资料及其元数据 |
| DocumentChunk | id、document_id、section_path、content、position、token_count | 可检索的最小知识单元 |
| Collection | id、name、description | 知识库集合 |
| QueryLog | query、mode、filters、latency、answer | 问答与问题排查记录 |
| EvalQuestion | question、expected_sources、reference_answer、tags | 标准化评测样本 |
| EvalRun | config、metrics、started_at、finished_at | 一次策略评测结果 |

## 10. 接口草案

| 接口 | 用途 |
| --- | --- |
| `POST /api/v1/documents/markdown` | 导入 Markdown 文档 |
| `POST /api/v1/documents/url` | 导入 URL 文档 |
| `POST /api/v1/collections/{id}/index` | 建立或重建索引 |
| `POST /api/v1/search` | 返回检索结果，不生成答案 |
| `POST /api/v1/qa` | 检索、生成回答并返回引用 |
| `POST /api/v1/evaluations/runs` | 运行评测集 |
| `GET /api/v1/evaluations/runs/{id}` | 获取评测结果 |

接口是下一步技术设计的初稿，不要求在 Sprint 0 一次定死。

## 11. 非功能需求

- **可复现性**：依赖、环境变量、数据准备与启动方式都写入仓库。
- **可观测性**：保留请求链路的关键中间结果，方便定位“没有召回”还是“生成偏题”。
- **可维护性**：解析、切分、索引、检索、生成、评测按模块隔离。
- **隐私与安全**：MVP 仅处理用户主动导入的公开资料；密钥只通过环境变量传入，不提交仓库。
- **中英文支持**：资料与问题允许中英文混合，第一版以中文提问体验为主。

| 阶段 | 交付物 | 完成标志 |

| Sprint 5 | 带引用问答 | 可完成端到端问答闭环 |
| Sprint 6 | 评测集与报告 | 有量化指标和策略结论 |
| Sprint 7 | Web 页面与 Docker 交付 | 他人可复现并体验项目 |

## 13. MVP 决策记录

以下内容已经确认，将作为 MVP 的实施边界：

| 决策项 | 已确认的选择 | 原因 |
| --- | --- | --- |
| 知识范围 | 只聚焦 RAG、Agent、LLMOps | 主题集中，便于沉淀高质量资料并体现 AI 工程方向 |
| 首版资料来源 | 官方文档 + 高质量技术文章 | 优先保证来源可信、可引用、可评测 |
| 学习路径生成 | 不纳入 MVP | 先完成导入、检索、引用问答和评测的核心闭环 |
| 部署方式 | 本地 Docker 演示 | 降低第一版交付难度，先保证他人可复现 |

公网 Demo、PDF 解析、学习路径生成和更宽泛的工程基础知识库，均作为后续版本的候选功能。
