# RAG 检索基础：从召回到引用回答

> 类型：学习笔记  
> 主题：RAG、检索、混合检索  
> 来源：基于官方文档与技术资料整理  
> 更新时间：2026-09-08

## 1. RAG 是什么

RAG（Retrieval-Augmented Generation，检索增强生成）是一种先从外部知识库检索相关资料，再将资料作为上下文交给大语言模型生成回答的方案。

它适合解决两类问题：

1. 模型训练数据过旧，无法覆盖最新资料。
2. 回答需要明确依据，用户需要回到原始来源进行核验。

一个基础 RAG 流程可以概括为：

```text
用户问题
  -> 检索相关知识片段
  -> 将片段组装为上下文
  -> 大模型基于上下文生成答案
  -> 返回答案与来源引用
```

## 2. 为什么不能直接把整篇文档交给模型

技术资料可能很长，直接将整篇文档放入提示词会带来问题：

- 上下文长度有限，长文档可能超过模型限制。
- 无关内容会干扰模型，降低回答准确性。
- 每次请求传入大量文本，会增加延迟和成本。
- 很难定位答案具体来自文档中的哪一段。

因此，RAG 会先把文档切分为多个 chunk，再以 chunk 为最小单位建立索引和检索。

## 3. Chunk 的设计原则

一个 chunk 应尽量表达完整的小主题，同时不能过长。

常见策略包括：

### 3.1 固定长度切分

按固定字符数或 token 数切分，并让相邻 chunk 有少量重叠。

优点是实现简单；缺点是可能会把一个完整概念、代码块或标题与正文拆开。

### 3.2 按标题切分

Markdown 和 HTML 通常有标题层级。先按标题切分，再对过长章节继续按长度切分，可以保留较好的语义结构。

本项目 MVP 将采用“标题优先 + 长度兜底”的策略。

### 3.3 保留来源信息

每个 chunk 至少应保留：

- 所属文档 ID
- 标题路径
- 在原文中的顺序
- 原始来源 URL
- 文档类型与主题标签

这些信息使系统能够展示引用，也支持按资料类型或主题过滤。

## 4. 向量检索与关键词检索

向量检索会将问题和 chunk 转换为 embedding 向量，通过向量相似度找语义接近的内容。

关键词检索通常使用 BM25 或全文检索。它对专业术语、函数名、版本号和精确短语往往更敏感。

例如，当用户搜索 `Qdrant payload filter` 时，关键词检索可能比纯语义检索更容易命中包含这个精确短语的资料。

## 5. 混合检索

混合检索同时使用向量检索和关键词检索，再融合两边的候选结果。

一种常用的融合方法是 Reciprocal Rank Fusion（RRF）。RRF 主要依据每个结果在不同排序列表中的名次进行融合，而不是直接比较不同检索系统的原始分数。

混合检索的优势是：

- 向量检索可以处理语义相近但表达不同的问题。
- 关键词检索可以保留专有名词和精确匹配的优势。
- 融合后通常比单一检索策略更稳定。

## 6. 回答必须引用证据

RAG 系统不应只返回自然语言答案，还应返回答案依据的 chunk。

当证据不足时，系统应该明确说明“知识库中未检索到足够证据”，而不是将模型自身知识伪装成知识库结论。

本项目的回答会尽量使用以下结构：

```text
结论
说明
证据来源
延伸阅读
```
